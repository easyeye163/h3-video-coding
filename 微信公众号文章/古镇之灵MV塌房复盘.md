# 我在嵩口古镇的 AI MV 塌房史：从烧掉 350 个币，到 60 秒成片

> 这篇不是教程，是一次完整的翻车复盘。我把我踩过的每一个坑、烧掉的每一笔币、以及最终如何拿到 60 秒对口型 MV 的全过程，老实讲给你听。
> 你可以把它当一个故事读，也可以当一份避坑地图用。

---

## 写在前面：这个故事为什么值得讲

先交代背景。我在给福建永泰的嵩口古镇做一个仙侠 IP——一个名叫林小溪的少女，青色汉服，白色簪花，在千年古镇的山水间吟唱。项目里有一条完整的内容产线：AI 写歌、AI 生成画面、AI 做对口型演唱 MV。

我原本以为，工具都现成，流程十几分钟就能跑通。

结果，我从写歌词到拿到第一段能看的成片，花了整整一天，烧掉 350 多个平台币，中间经历了五次想砸键盘的失败。

这篇文章记录的就是这条产线从「全空」到「跑通」的全过程。我不会把代码整段甩给你——那些模板仓库里都有——我讲的是**代码不会告诉你的东西**：问题出在哪、为什么出、以及我最后怎么绕过去的。

---

## 一、第一课：所有的"AI"，先把它当成一台盲盒机

我第一次接触这个 AI 视频平台时，以为像用 App 一样：选个模板，点生成，完事。

错。它真正的运行方式很"原始"：

- 你在网页上看到的每个"模板"，本质是一个叫 **AI 应用（ai-app）** 的东西——它是一组输入框 + 一个后台任务管线
- 每个输入框有一个编号（nodeId），你调用时不是"点击"，而是**用 API 把参数挨个塞进对应编号的框里**
- 塞进去之后，它不会马上给你结果，而是先甩给你一个**任务号（taskId）**，让你每隔二三十秒自己回头查一次，查到最后给你一个**临时下载链接**

一句话总结这段经历：**这不是生成，是点外卖之后自己反复刷新看骑手到哪了。**

而且它很烧钱。截一张我真实的账本：

| 环节 | 一次成本 | 我的心在滴血 |
|---|---|---|
| AI 音乐生成 | 约 50 币 | 一首歌一首歌烧 |
| 语音转字幕 | 约 8 币 | 便宜，但被坑过一次 |
| 单段 15 秒视频 | 约 86 币 | 做错了等于白烧 |
| MVP 总投入 | **350+ 币** | 大约一顿外卖钱 |

所以第一个血泪结论：**动手前先想清楚参数，AI 不便宜，试错要挑着试。**

## 二、第二课：给 AI 写歌词，不是写"词"，是写"导演脚本"

我第一版歌词就是一行行句子丢进去，结果 AI 生成的歌毫无起伏，副歌和主歌一个样，难听到我直接想放弃。

后来才明白：MiniMax H3 这种"文本直接出歌"的模型，它要的不是词，是**带分镜的脚本**——你得告诉它：开头是什么氛围（前奏）、哪里进入第一段、哪里进副歌、尾声怎么收。

这是我后来整理出的、实测有效的写法，它长这样：

```
【曲风构想】
中慢速中国风慢摇，古筝与二胡交织，深沉的 Bass 驱动四拍子鼓点，
清亮女声，温柔唯美，适合古镇夜景。速度约 80BPM，情绪含蓄深情。

(Intro 前奏)
（无人声，只写配器和氛围）

(Verse 1 主歌一)
（第一段，情绪铺垫的几句词）

(Chorus 副歌)
（全曲最有记忆点的几句，这里决定了后面 MV 切哪段）

(Outro 尾声)
（如何收尾）
```

注意那几个括号不是装饰，是**给 AI 的分镜指令**。我没标括号时它是乱的，标了之后副歌终于"对味"了。

还有个参数叫 `cfg`，类似"提示词力度"。我试过一个范围，**1.7 最好用**：太低歌会跑调，太高编曲硬得像机器人。这个数字是拿币试出来的，不是看说明看来的。

> 可复用结论：给"文本生成音乐"类的 AI 写输入，本质是当导演——你越把情绪、结构、配器指挥清楚，它越听话。

## 三、第三课：中文是万恶之源，命令行尤其如此

这是我今天最无语的一个坑，但它值得单独讲，因为太隐蔽了。

我写好歌词，直接拿命令行去调音乐生成的接口，把整段中文 JSON 粘在 curl 后面。结果服务端回我一排错误码 1007：`failed to parse request body`——请求体解析失败。

我一度以为是接口参数写错了，反复改格式。

后来试出真相：**中文在命令行里经过 shell 转义，再经编码处理，很容易就"脏"了，服务端拿到的是坏掉的数据。** 跟参数对不对根本没关系。

解法极度土味但极度有效：**把 JSON 存成一个文件，让它从文件读，别从命令行读。**

```bash
# 把写好的 JSON 存成 payload.json，然后：
curl -X POST "https://www.runninghub.cn/openapi/v2/run/ai-app/2094807049065558018" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${RUNNINGHUB_API_KEY}" \
  --data @payload.json
```

从那以后，凡带中文的提交，我全部走文件，再没出过 1007。

> 可复用结论：调中文接口，别跟 shell 的转义较劲，用"读文件"绕过去。这条省下我至少一小时。

## 四、第四课：一首歌 3 分钟，可 AI 视频一次只肯做 15 秒

歌出来了，2 分 59 秒，我很满意。然后我天真地想：直接把整首歌喂给视频生成，一步到位。

结果后台直接报 `torch.OutOfMemoryError`——显存炸了，任务失败，**币照扣**。

这是整个项目最重要的一条硬约束，写在文档里没人告诉你是真的：

> **这个视频生成模型，一次最多只能做 15 秒。**

一次 15 秒，意味着 3 分钟的歌要拆成 12 段。而拆在哪，是有讲究的——不是随意切，而是要切在**歌词的完整句子上**，保证每段画面有完整的一句在唱。

怎么找到精确的切割点？靠语音识别（ASR）。它能把歌曲转成带毫秒时间轴的字幕，告诉你每一句词从第几秒开始、第几秒结束：

```
00:01:11,000 --> 00:01:15,000
溪水泛尽处 又见青山
```

我按这个时间轴，在副歌区域依次切出 71、86、101、116 秒四段的 15 秒音频，对应四句完整的歌词——这四段就是 MV 的四个镜头。

> 可复用结论：AI 工具的"单次上限"比文档描述的更狠，先做最小可行性测试（比如先做一版 15 秒）再放大，能省下大把冤枉币。

## 五、第五课：最贵的一课——它不做对口型，除非你"指名道姓"

四段音频切好了，角色图、场景图都备齐，我开始生成视频。

第一次出片，画面很美：林小溪在古镇夕阳里，很梦幻。**但她闭嘴没唱。** 嘴型一动不动，配着歌声，违和到我瞬间血压拉满。

我查了很久，最后在一份提示词模板里找到了玄机：

> 想让角色"张嘴唱"，歌词必须包在一个叫 `<d>[Chinese]...</d>` 的标签里。

`<d>` 是啥？是"数字人模式"的开关。你把这个标签写上，模型才进入对口型演唱模式；不写，它就当纯背景音乐，人物当风景画处理。

于是我把剧本写给 AI 的那段描述，改成这样明说：

```text
她唱着歌曲，口型与歌词逐字同步，眼神温柔望向远方。
<d>[Chinese] 若你也曾路过这人间，请听古镇轻轻把歌唱完。</d>
```

同样一段词，加不加这个标签，出来的完全是两个物种。这是我今天花得最值的一笔币——因为它是**认知差**，不是操作差。

> 可复用结论：AIGC 的"高级功能"往往藏在特定语法里，网上教程很少写。遇到"怎么调都不对"，去翻模板/官方示例的原文，找特殊标记。

## 六、第六课：给 AI 的剧本，其实有固定格式

标签解决了"唱不唱"，但我还发现一个更底层的规律：**这个模型的提示词不像写作文，更像填六格表格。**

它内部有六段固定结构，每段职责分明：

1. `subject_definitions` —— 先自我介绍：哪个图是角色、哪个图是场景、哪段音频是歌声
2. `summary` —— 一句话说清：这是一支"参考图+音频 → 角色对口型演唱"的 MV
3. `retention_analysis` —— 告诉它什么必须保留：角色长相 100% 保留、场景 100% 保留、**音频 100% 原样复制**
4. `detailed_description` —— 写清镜头怎么构图、人怎么动，**并在句子里嵌 `<d>` 歌词**
5. `overall_soundscape` —— 人声之外，环境底噪（水声、晚风）的描述
6. `non_diegetic_music` —— 有没有额外配乐（我这场景写 N/A）

我一开始把提示词写成一大段散文，AI 抓不住重点，画面和歌词对不齐。按这六格老老实实填了一遍之后，效果立刻就稳了。

这个认知的含金量在于：**它把"玄学提示词"变成了"填表"。** 以后再换曲子、换场景、换角色，我一分钟能写一版，因为它就是填空。

> 可复用结论：很多 AI 视频/音乐模型内部对提示词有隐含的"schema"。与其自由发挥，不如找到那个骨架照着填——稳定性和效率翻倍。

## 七、第七课：AI 平台的"防呆"设计，其实处处是坑

这一段是我一路滚过来的真实地雷，列出来给你省命：

**雷一：并发限流。**
我提交第一段后没等完成就提交第二段，被服务端一个 421 错误拦下。查了才知道：**同一个模型同时只能跑一个任务**。从此我学会了老老实实串行：第一段 SUCCESS → 下载 → 再提交第二段。4 段就是 4 次等待，每次约 7 分钟。

**雷二：中文文件名直接喂进去会翻车。**
我用中文命名的场景图（比如 `04_万安夕照.png`），丢给接口，服务端回 `Failed to fetch URL`。解决方式是把中文做一次 URL 编码再提交。二十六个字母加几个符号的事，卡了我一刻钟。

**雷三：任务结果链接是临时的。**
每段视频生成完有个下载链接，但它是腾讯云 COS 的临时链接，**约 24 小时就失效**。有一次我没及时下载，第二天再点已经 404。教训只有一句：出结果立刻下载，别攒着。

**雷四：一次性塞整份音频 = 白烧钱。**
前面说过了，整曲提交直接 OOM 失败，币不退。这条值得在表格里再出现一次，因为太容易犯了。

> 可复用结论：AI 平台的边界（并发、字符、时效）都是真金白银换来的教训，开工前花 5 分钟读一下官方文档的限制说明，比烧币试错划算得多。

## 八、收尾：60 秒成片，和它买不到的东西

四段都生成完，我用 ffmpeg 把四段 15 秒片按顺序拼起来：

```bash
ffmpeg -f concat -safe 0 -i concat_list.txt -c copy mv_guzhen_ling_full.mp4
```

60 秒完整 MV 到手。从写词到成片，全程半小时到一小时；如果我不把那些学费算进去的话。

但我想说的其实是另一件事。这一整天下来，我越来越清楚一个边界：

**AI 替我省掉的，是"把歌做出来、把画面做出来"的物理成本——它没替我省掉的，是"我到底想表达什么"。**

歌词里的嵩口、大樟溪、古榕、万安夕照，是我的眼睛真正见过的古镇；林小溪这个角色，是我们这个 IP 从零长出来的；甚至那些翻车的瞬间——OOM、1007、闭嘴不唱——都成了只有我能讲、别人抄不走的故事。

技术是杠杆，内容是支点。这句话我写进每篇复盘，这一次是真正摔出来的体会。
